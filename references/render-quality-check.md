# 人工启动 Remotion 与渲染质量检查（第 10 步）

## 启动边界

第9步交付后自动停止。只有操作者主动进入本步，才讨论预览、关键帧、短片段和最终成片；agent 不自动运行 Remotion 关键帧、短片段或最终 MP4。用户说“做视频”或批准生产方案，不等于批准自动渲染。

先重新读取目标项目的 `package.json`、Remotion配置、Composition注册与生产scenes.json，再给人工可执行命令。不能假定已有dev/render脚本、Composition名或out文件名，更不能把Skill根的package当视频项目。

- package实际有 `dev` 指向Remotion Studio才建议相应 `npm run dev`；有start才建议 `npm start`；有render才给其实际 `npm run render` 及输出路径。
- package无对应脚本时说明当前情况，依据已安装Remotion版本/CLI帮助给经过核对的命令，由操作者手动启动；不臆造npm命令或为检查擅自创建执行脚本。
- 新项目仍须复用全局Chrome，缺失或不兼容先人工处理，不以渲染触发重复下载。
- `out/`只存最终MP4；人工 QA 关键帧、临时片段与检查记录用项目根 `制作过程/渲染质检/`，不污染out/。

## 证据与结果标记

没有渲染产物时只记录“未渲染/视觉未验证”。类型检查、JSON检查、源码知识兑现审查不能证明画面可读、动效连续或音画同步。仅封面PNG通过也不能推及视频画面。

操作者提供产物后实际读取图片/播放或分析可访问的视频与音轨，注明文件、scene、帧/时间范围、检查方式与覆盖范围。没有实际看/听到的范围标未验证，不能声称全片通过。静帧能支持静态版面判断，不能证明正常速度节奏通过。

## 抽查范围

每条新视频至少检查四类镜头：开头、最高信息密度/最复杂知识镜、主要转折、结尾。新增组件或试点还需正常速度短片段与一个边界样例（长文字/最多元素/短时长/不同底色）。由操作者人工启动产物生成，不把“必要QA”解释为agent默认可渲染。

同时按全片看主题一致性、镜头语法密度、推拉方向和知识覆盖。抽查通过仅表示抽查范围通过，不能写全片无缺陷。

## 检查表

| 类别 | 核对内容 | 证据 |
|---|---|---|
| 知识与证据 | 主张数字、尺度、坐标、因果与来源一致；相关不被画成因果；生成图不冒充真实史料 | 研究/计划对照实际画面 |
| 静态可读性 | 2秒能辨认主体、关系与文字；无遮挡、错位、截断、豆腐块，信息稳定可读 | 关键帧与实际字形边界 |
| 色板与背景 | 全片同六键与亮暗范围；paper暖浅底；无新项目星空/渐变/无意义光晕；遮罩同bg | 各关键帧与palette.ts |
| Typography | 新项目review-v1-fixed完整角色，顶部标题52/800/黑体、知识胶囊44/900、字幕70/600/文楷，特殊钩子96与符号140显式规划；旧ep5-v2-fixed仅原项目兼容，不动态缩字 | 计划角色、实际字体/合成粗体与画面 |
| 安全区 | top≥150、左右≥40；主视觉建议止于1360；字幕top1440、左右≥56、bottom≥250；y1700–1920无内容 | 1080×1920帧 |
| 默认禁项 | 无未授权eyebrow/品牌带/视频进度条/英文chip，不因旧项目有而自动加 | 开头、转折、结尾 |
| 动效知识关系 | 正常速度能看出因果/流程/对照/结构，不只是元素在动；每镜主辅模式有序 | 正常速度片段 |
| 连贯与镜头 | 视觉锚点承接，有意变构图/层级；无突跳或方向打架，不连续三镜向内推；snap有理由 | 相邻镜片段、全片时间轴 |
| 字幕与声音 | 70px单行≤13视觉字符、无nowrap挤压，去尾标点；不溢出segEnd，跟真实人声，默认中文 | 正常速度听看与实测startSec |
| 音频 | 无吞字/错读/英文混排失真，默认gentle_female；-16.60LUFS、开场0.9已处理且未重复降速 | 音轨试听及后处理记录 |
| Outro | 独立回顾无新知识，尾部2.0–2.5s只呼吸/渐隐；最后元素在有声区间完成，字幕不摊入静场 | 最后一镜与最后30–35帧 |
| 最终文件 | 如人工已出片，核对尺寸1080×1920、25fps、完整音轨/时长与期望输出；无MP4不写“成片已完成” | 实际文件元数据与播放 |

## 失败回退与批准重置

| 问题 | 返回步骤 | 审批处理 |
|---|---|---|
| 来源、数字、机制或确定性错误 | 第2步研究，继而第3–5步改写 | 改计划则版本+1、pending，重评后第6步批准 |
| 核心知识遗漏、顺序、钩子、情绪或Outro内容 | 第3步叙事，再第4–5步 | 重置批准并回第6步 |
| 表达方法、shotLang、组件、动效意图、色板或字号方案错误 | 第4步规划，再第5步评测 | 重置批准并回第6步 |
| 实现偏离有效批准方案、遮挡、出界、注册/路径错误 | 第7步实现 | 纯恢复批准意图可保留内容审批，记录修复；若改方案须重审 |
| 音频错读、实测durationSec/startSec、字幕时间、开场后处理 | 第8步同步 | 仅测量/等价发音修复按计划处理；改旁白或计划意图须重审 |
| 封面背景/版式/发布文案不一致 | 第9步 | 恢复方案可直接修；改主张、主题等须重审 |

修复后执行对应非渲染检查，再停止等待人工重新生成检查产物。不能自动渲染来“验证修好了”，也不能沿用修复前截图作为新版本通过证据。修改计划时统一清空reviewedVersion与批准记录，不因已经有MP4就跳过第6步。

## 汇报口径

记录检查对象版本、实际产物路径、抽查scene/时间、通过项、失败项、未覆盖项及返工步骤。未获得正常速度证据时单列动效/字幕对齐未验证；新增组件未完成渲染与边界样例时不能宣称正式库准入完成。不得在无数据时声称新模式库已降低成本或提升播放效果。
