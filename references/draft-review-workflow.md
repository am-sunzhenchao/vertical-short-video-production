# 草稿评测、同步与人工审批（第 5–6 步）

## 第 5 步：完整方案落盘

读取 `制作过程/原始知识材料.md`、`制作过程/知识解析与证据.md`、`video-plan.md` 契约，将叙事和逐镜规划写成同一 `planVersion` 的 `制作过程/视频制作方案.json` 与 `制作过程/视频方案审阅稿.md`。科学审查表从 `制作过程/知识解析与证据.md` 汇入同一审阅稿，镜头正文也合并在此，不另建草稿视图或审查文件。本阶段允许写研究/方案文档及临时统计输入，不写生产代码、生成素材或配音。

草稿必须含 Step 4 的 4A–4D 知识兑现与跨批衔接检查证据，不能只凭字段齐全或总分放行；具体执行见 `visual-planning-workflow.md`。

草稿必须含研究摘要/来源、关键主张核验状态、叙事大纲、完整逐句旁白与字幕、知识覆盖、场景表、整片色板实际六键与 typography 版本、全部逐镜视觉/组件/动效参数、Outro、下述评测、压缩比四项与衔接检查表。主题覆盖仅操作者明确要求时记录，不把选风格或音色设成必填确认。

### 改编原则检查

用三项有依据的检查替代旧“改编硬规则”引用：有依据扩写、不无谓重复、钩子不注水。补充解释要服务核心问题；总览与细讲有增量即可保留；钩子真实且有兑现。扩写与压缩比均不设上限，单镜与全片不设时长上限，5–10 分钟知识片也合法；不为压时长删论点或过渡镜。

## HKRR 草稿检查表

| 要素 | 核心目标 | 草稿落点检查 |
|---|---|---|
| H · Happiness 快乐 | 趣味解压、猎奇、视觉爽感 | 是否有合题材的反转、幽默或结构拆解爽感？不为 H 编造内容或滥用爆炸 |
| K · Knowledge 知识 | 干货、避坑、科普、内幕 | 每个知识镜是否有明确知识目标？观众能理解或落地吗？ |
| R · Resonance 共鸣 | 情绪共情、经历、价值认同 | 普通人能否代入？有无真实困惑或“说出心声”的情境？ |
| R · Rhythm 节奏 | 开篇抓眼、信息节拍、快慢区分 | 前3秒能否建立问题？约每15秒有有效看点吗？收束有记忆点吗？ |

四项都强是传播潜力参考，至少覆盖两项才具备传播基础的建议不是播放效果保证；四项均检查，缺项写补充方案，不强制每镜同时出现四项。可参考何同学《5G 真实速度》、影视飓风《粉丝卫星》的知识与节奏结合，不以参考片代替证据核查。

## 7 维度量化评测

逐项对照原材料与研究底稿，1–10 分，计算加权总分；每项给具体 scene/claim 依据。

| # | 维度 | 权重 | 评判要点 |
|---|---|---|---|
| 1 | 内容忠实度 | 15% | 核心观点和信息是否保留？有无遗漏、扭曲、过度发挥？证据纠正是否记录？ |
| 2 | 开场钩子 | 20% | 前3–5秒能否抓住注意力？有真实悬念、冲突或情绪冲击？避免平淡开场和夸张注水 |
| 3 | 叙事结构 | 15% | 钩子、展开、高潮、收束清楚吗？信息密度合理、转场自然吗？ |
| 4 | 视听可执行性 | 15% | 画面能否直接指导实现？旁白字幕口语化吗？组件、参数、BGM/音效意图合理吗？ |
| 5 | 情绪曲线 | 15% | 有明确情绪走向、中段转折或喘息点、结尾记忆点/行动引导吗？ |
| 6 | 平台适配度 | 10% | 9:16、社交传播、语速和单镜密度适配吗？不因总时长长扣分 |
| 7 | 制作可行性 | 10% | 现有组件、素材、特效可实现吗？是否过度依赖高成本制作？不得虚称已验收 |

### 评分输出模板

```text
## 草稿评测结果（第N轮，planVersion=V）
| 维度 | 得分(1–10) | 简评与依据 |
|---|---|---|
| 内容忠实度 | | |
| 开场钩子 | | |
| 叙事结构 | | |
| 视听可执行性 | | |
| 情绪曲线 | | |
| 平台适配度 | | |
| 制作可行性 | | |
加权总分：XX/10
最终判定：可呈现 / 需优化后重评 / 需重写
修改建议：按P0–P5，逐条列问题 → 改法 → 预期效果
```

- 正常可呈现：总分≥8且核心维度1–5无单项≤5。
- 需优化：总分6–7.9，或核心维度1–5任一≤5。
- 需重写：总分<6。
- 分数只放行人工 Review，不自动批准生产；证据、知识丢失与版本门禁不能被高分抵消。

### 自动优化迭代

1. 不通过按 P0→P5 自动优化，每次变更同步 JSON/草稿、增加版本、重评所有表。
2. 最多3轮：第1–2轮自动优化+重评；第3轮仍不通过呈现最优版与剩余问题，由操作者决定继续修改或接受。
3. 优先级：P0 情绪断裂（连续K轰炸/缺共鸣）；P1 信息过载（单镜多知识点或语速过快）；P2 核心内容遗漏；P3 冗余拖沓；P4 视听描述不具体；P5 过渡生硬。高风险事实问题先回第2步处理，不以优先级延后。
4. 接受有评分残留版本须明确记录残留和接受依据，仍不得接受未处理的高风险确定性陈述、核心知识丢失或无有效审批版本。

## 衔接连贯性检查（第 5 步放行前）

逐相邻镜 `S(n) → S(n+1)` 过三问，尤其关注跨章节和知识层级转换。

| # | 检查项 | 判断方法 | 不通过的处理 |
|---|---|---|---|
| ① | 叙事是否承接 | 上一镜落点能接住下一镜开头吗？同话题层级吗？ | 加“结果+设问”过渡或改开头。如逐条判定后问整体是否值得 |
| ② | 画面是否延续 | 同图形放大、拆开、汇总，还是无理由另起一套？ | 共享元素/位置/强调色锚点：卡片缩为下镜一行、同位置生长；颜色只能用批准色板 |
| ③ | 口播是否有连接词/回指 | 有“但/所以/到这一步/那么”或回指名词吗？ | 补承接语；新概念先说明为什么此时讲它，不机械每句加连接词 |

| 跳变类型 | 过渡镜写法 | 示例 |
|---|---|---|
| 换章节：流程→判定、判定→统计 | 结果 + 设问 | 第一轮跑完，你手里只有一堆输出。它到底算合格，还是不合格？ |
| 换视角：逐条→整体、整体→逐条 | 缩放隐喻，点明视角变化 | 平均值会掩盖细节，真正有用的信息藏在逐条断言里 |
| 换主体：机器→人、断言→人工 | 边界声明，说明前手段的盲区 | 断言只能覆盖你预想到的东西，想不到的问题还得靠人看 |

```text
## 衔接连贯性检查
| 相邻镜对 | ①叙事承接 | ②画面延续 | ③口播钩子/回指 | 结论/处理 |
|---|---|---|---|---|
| S01 → S02 | 通过 | 通过 | “所以” | 通过 |
| S08 → S09 | 跨章节 | 元素另起 | 硬起概念 | 补过渡S08C，S09复用尺子图形，重评 |
相邻镜对总数：N；通过：N1；补过渡：N2；调整画面：N3
新增过渡镜清单：...
```

所有不通过项必须落实处理并复查，不留“已知但不处理”。过渡镜是结构必需件，不受时长与压缩比影响；画出上镜收束+下镜雏形，不能只放一句标题。镜头语法承接或异族对比须有意图，参见第4步规范。

## 文稿压缩比统计（四项缺一不可）

统计用途是观察改编幅度，不是控制长度。高读数检查书面语，低读数检查论点是否丢，>100% 表示口播扩写也合法。不手工口算字数或总时长。

### 计算口径与临时导出

| 指标 | 定义 |
|---|---|
| 原始汉字数 R | 制作过程/原始知识材料.md 按现有模板剔除 Markdown标记/标题/引用行/表格/代码块后，正则 `[\u4e00-\u9fff]` 计数 |
| 口播汉字数 N | 各镜 narration 拼接，主指标不含标点/空白 |
| 压缩比 | N/R，无上下限，不作门禁 |
| 精简字数 | R−N；负数报告“净增”，不要伪称精简 |
| 总/逐镜语速 | 汉字数/有声秒数，PAD与tailSec不作为人声时间 |

直接使用Skill维护的 `scripts/script-stats.mjs --raw <原始材料绝对路径> --plan <方案绝对路径>`；不为每部视频重写统计代码，不提前生成生产scenes.json。计划统计明确estimated并扣除tailSec与PAD；Step8可改用 `--scenes <生产scenes.json>` 按audioDurationSec统计measured时长。旧工具需要兼容统计输入时才导出到项目 `制作过程/临时文件/`，不能把estimatedStartSec当作真实起点。

命令中的路径必须先解析，`--help`给出当前接口。R=0时压缩比为N/A，不输出Infinity；统计正文过滤局限仍按下文记录。

若 raw 有大量表格/代码导致 R=0 或原始有效文字不完整，写明过滤局限，压缩比记 N/A，不输出 Infinity/NaN。核对脚本实际统计口径，不声称它已处理未支持的格式。第8步最终音频后用实测有声时长再统计，不把第5步估计语速当实测。

### 压缩比读数

| 读数 | 含义 | 建议（非门禁） |
|---|---|---|
| 偏高 | 可能接近照读、书面语多 | 改从句/连接词为口语，不为降比例删论点 |
| 居中 | 常规改编 | 仍核对覆盖 |
| 偏低 | 收敛合并较多 | 逐条查核心论点 |
| >100% | 逐条展开、补机制、过渡或背景 | 确认有依据且不注水复述 |

### 语速参考与字幕路线

| 字/秒 | 字/分 | 判定 |
|---|---|---|
| <3.0 | <180 | 可能拖沓，检查朗读/留白，不自动删知识 |
| 3.0–4.5 | 180–270 | 健康参考 |
| 4.5–5.8 | 270–350 | 偏快，长镜拆句 |
| >5.8 | >350 | 语速门禁，必须放慢或拆句，不删论点 |

每镜语速极差 max−min≤1.0 字/秒 → 每 scene 整段 TTS + 字幕按汉字数比例分配；>1.0 → 多段 TTS + 实测 startSec 回写。第5步标 estimated 并写 `audioPlan`，第8步复核真实人声时长和字幕误差，不能声称仅凭均匀语速保证对齐。单段 TTS 不是全片合成一次；不对均匀的≤13字短句逐句合成破坏韵律。

### 精简内容归纳（固定 6 类）

| # | 类型 | 典型特征 |
|---|---|---|
| 1 | 重复表述 | 同观点换句话讲两遍 |
| 2 | 书面语连接词 | “在此之上，再去追求第三点”→“第三层” |
| 3 | 同类枚举收敛 | 多例子收为代表项，但不删互异机制 |
| 4 | 解释性从句 | 复杂限定结构改成口语主句，保留意义 |
| 5 | 限定/让步语 | 检查真冗余与证据必需限定，后者不删 |
| 6 | 段落复述合并 | 结尾重复前文路径的段落合并 |

逐类给原/改例子及字数量级，无该类写“无”。某类删减占比>40% 时检查是否误删论点，这不是新的压缩比阈值。归纳证明删掉冗余而非知识。

## 第 6 步：人工 Review、双向同步与停机

最终呈现完整研究与草稿、7维评分、视觉规划、压缩比四项、衔接表、优化摘要和待决策事项：

```text
## 草稿评测结果（第N轮，版本V）
[7维度表及最终判定]
### 优化摘要
| 轮次 | 优化前总分 | 优化后总分 | 关键改动/版本 |
|---|---|---|---|
待用户决策项：残留问题/主题覆盖/证据缺口等
审批对象：制作过程/视频制作方案.json planVersion=V 与同版 制作过程/视频方案审阅稿.md
状态：pending，等待明确批准
```

1. 操作者明确批准当前方案版本前，停止，不写生产代码、不生成素材、不配音；“评分通过”或模糊的旧版本“开始”不是审批。
2. 批准前重新 read 文件。若人工改 `制作过程/视频方案审阅稿.md` （含其中的镜头正文），重新读取→回写计划所有差异→版本+1→重置pending/清空reviewedVersion→同步草稿→重评→再批准。JSON 直接改动同理。
3. 批准后 `review.status=approved` 且 reviewedVersion=planVersion；仅审批状态变化不增加版本。修改任一计划字段令批准失效。
4. 第7/8/9步开始前重新读取计划、草稿全字段，确认版本、审批、评测与全部配置/逐镜参数一致，之后再运行已生成项目的 `check-draft-sync.mjs`。
5. 新项目用 `render-review.mjs` 从方案生成同版全字段视图，兼容每镜 `**S01｜标题**` 下字幕全文引用；手工修改视图须先读差异并回写计划，不用刷新覆盖用户内容。
6. 批准后用 `export-plan.mjs` 导出生产数据，保留仍有效的真实音频时长与起点；用 `validate-project.mjs`核对全字段、角色、审批和组件，用typecheck做类型检查。旧 `check-draft-sync.mjs`仅检查部分旁白，不保证样式、参数或版本一致。
7. 不变更设计意图的路径/类型实现bug与音频实测可保持版本；主动更改字号、字体、标签内容、布局或motionPlan则必须版本+1、重评与明确批准。所有脚本缺失/差异/冲突均阻塞，不使用allow-missing放行。
