# 动效系统：知识表达 → 运动模式 → Remotion 组件

> 目标：降低不同模型写出的动画差异、减少 review 与返工。模型负责做有边界的导演决策；稳定的运动逻辑由已验收的 Remotion 组件执行。不要每个 scene 都从零发明动画。

## 1. 三层分离

1. **知识表达层（为什么动）**：过程、因果、对比、结构、空间路径、数据变化、误区纠正、总结等。先写观众应该理解什么关系。
2. **标准运动模式层（怎么动）**：从下方 12 种模式中选择；每镜一个主模式，最多一个辅助模式。
3. **组件与视觉主题层（长什么样）**：Remotion/React/SVG 组件负责实现；色板、字体、描边、背景、缓动构成主题。不得把主题风格和运动语法绑死。

选择顺序固定：`knowledgeGoal → knowledgeRelation → primaryPattern → existingComponent → params → visualTheme`。只有现有组件确实无法表达知识关系时才新增组件。

## 2. 标准动效模式目录

模式 ID 是稳定接口名，不要求组件文件名必须相同。先将已有 Effect 映射到模式，再决定是否开发新组件。

| ID | 模式 | 最适合表达 | 核心动作 | 禁止/风险 |
|---|---|---|---|---|
| `SEQUENTIAL_REVEAL` | 逐步揭示 | 步骤、枚举、时间线、层级 | 元素按语义顺序出现，出现后稳定保留 | 每项都弹跳/旋转；装饰动作盖过信息 |
| `SCALE_EXPANSION` | 尺度扩张 | 范围、规模、扩散、微观到宏观 | 从指定中心扩张，轮廓/范围逐步出现 | 无依据地放大所有对象；尺度不一致 |
| `CAUSE_EFFECT` | 因果联动 | 机制、原因与结果、系统工作方式 | 原因 → 中间机制 → 结果，连接关系同步显现 | 只有三个卡片依次淡入，却未表达关系 |
| `STRUCTURE_EXPLODE` | 结构拆解 | 组成、层级、内部结构 | 部件沿明确轴线拆开，再可选重组 | 部件随机漂浮、拆后无法辨认整体 |
| `SIDE_BY_SIDE_COMPARE` | 对照比较 | 前后、A/B、误区与事实 | 同尺度并列，差异项单独强调 | 两侧尺度/时间不一致，造成误导 |
| `FLOW_FIELD` | 流场与路径 | 空气/液体/能量/信息流、迁移路径 | 沿明确路径移动，方向、密度和速度受控 | 随机粒子冒充科学流动；错误暗示真实机制 |
| `FOCUS_CALLOUT` | 局部聚焦 | 细节、关键证据、复杂图表 | 框选目标 → 局部放大/引线解释 → 稳定停留 | 反复推拉；放大后丢失空间参照 |
| `MORPH_SEQUENCE` | 连续形态演化 | 生长、阶段变化、形态转换 | 关键状态之间连续变形或逐阶段构建 | 不相关图形交叉淡化，伪装成形变 |
| `DATA_BUILD` | 数据逐步构建 | 趋势、统计、实验、数值 | 曲线按数据绘制、柱形按数值增长、拐点高亮 | 图形数值与真实数据不一致；坐标误导 |
| `BRANCHING_PATH` | 分支路径 | 分类、决策树、不同后果 | 起点 → 分支 → 节点，按逻辑层级展开 | 线条交叉、视觉连接与真实逻辑不符 |
| `QUESTION_REVEAL` | 提问与揭晓 | 反直觉、误区纠正、开场悬念 | 先提出问题/建立预期，再揭晓关键机制 | 过多特效、答案尚未讲清就切走 |
| `SYNTHESIS_LOCKUP` | 汇总与定格 | 结论、框架回收、章节收束 | 分散信息汇聚为稳定布局，留阅读时间 | 结尾仍持续运动，观众无法消化 |

### 默认选型映射

- 步骤/枚举/时间顺序 → `SEQUENTIAL_REVEAL`
- 原因、机制、结果 → `CAUSE_EFFECT`
- 物体大小或影响范围变化 → `SCALE_EXPANSION`
- 内部构成与部件关系 → `STRUCTURE_EXPLODE`
- 前后或 A/B → `SIDE_BY_SIDE_COMPARE`
- 物质/能量/信息沿路径运动 → `FLOW_FIELD`
- 细节、证据、局部结构 → `FOCUS_CALLOUT`
- 同一对象连续变形 → `MORPH_SEQUENCE`
- 数值、曲线、比例 → `DATA_BUILD`
- 分类、选择、分叉 → `BRANCHING_PATH`
- 反直觉、问题后揭晓 → `QUESTION_REVEAL`
- 总结、结论、知识框架 → `SYNTHESIS_LOCKUP`

如一个 scene 有多种知识关系，优先选择最直接服务旁白主张的关系，不要把多个模式堆叠成特效秀。

## 3. 模型输出契约：motionPlan

每个 scene 的分镜阶段必须写 `motionPlan`。字段缺失时先补齐，不得直接写 Effect 代码。

```json
{
  "knowledgeGoal": "观众看完这一镜应理解什么",
  "knowledgeRelation": "cause_effect",
  "primaryPattern": "CAUSE_EFFECT",
  "secondaryPattern": null,
  "selectionReason": "因画面要解释原因如何经过机制产生结果",
  "camera": "hold",
  "intensity": "low",
  "continuityFrom": "S02 的上升主体",
  "allowedMotion": ["reveal-link", "activate-result"],
  "forbiddenMotion": ["random-spin", "decorative-particles"],
  "evidenceRisk": "low"
}
```

允许值建议：
- `knowledgeRelation`: `process | cause_effect | compare | structure | flow | scale | data | branch | misconception | synthesis | atmosphere`
- `camera`: `hold | push | glide | pull | snap | cut`
- `intensity`: `low | medium | high`
- `primaryPattern`: 必须为目录中的一个 ID
- `secondaryPattern`: 仅当确有必要时填写一个模式，否则 `null`

`motionPlan` 描述意图，不替代 `scenes.json` 中的时长、字幕、音频等既有字段。首轮迁移可以将它作为 `scenes.json` 的可选对象；当现有管线无法保存嵌套字段时，先写入 `draft-review.md` 的镜头表，不要为此破坏现有数据结构。

## 4. 运动参数基线

以 30fps 为示例基线；项目若为 25fps，所有帧数按秒换算。具体数值需经试点渲染校准。

- 普通入场：8–16 帧；关键揭晓：12–20 帧。
- 普通位移：12–36 px；普通缩放默认 `0.94 → 1.00`。
- 错峰：4–8 帧；只有确有语义层级时才错峰。
- 普通元素默认不弹性回弹；禁止每个镜头都用同一入场动画。
- 单镜一个主动作，最多一个辅助动作；主动作结束后应有稳定阅读区间。
- 动画必须由 Remotion 帧驱动（如 `useCurrentFrame`, `interpolate`, `spring`, `Sequence`），不得依赖与渲染帧无关的浏览器定时器或 CSS 自动播放来决定关键状态。
- `spring()` 不是默认选项；只有物体具有弹性、碰撞、回弹等语义时才使用。
- 参数必须确定性：相同输入与帧号应得到相同画面；随机数必须固定 seed。

## 5. 镜头语言：动作是标点，不是句句修饰

参考 Huashu 的镜头语言原则，但用 Remotion 现有实现落地：

- **看得清就停**：画面本身在绘制/变化或观众需要读字时，优先 `hold`。停镜不是失败。
- **过渡缓，重音快**：`push`/`glide`/`pull` 用于引导视线；`snap` 只用于揭晓、反转、关键数字或强节拍。
- **推拉有来有回**：连续三镜不得全部向内推；推近后应考虑拉远、横移或切换景别。
- **节奏有变化**：不可每镜都缓推，也不可每镜都快切。镜头动作应服务段落功能与旁白节奏。
- **画面内运动优先于无意义运镜**：主体在动、曲线在画、结构在变化时，不必再叠加镜头移动。
- **转场承担关系**：只有在空间/时间/因果连续时才使用连续转场；否则清楚硬切通常更好。
- `snap` 是重音动作，不是通用入场动画。整片重音镜头需稀少，并在分镜阶段说明理由。

## 6. 组件映射与新增门槛

建立 `motion-patterns.md`（或在本文件维护）映射表，字段至少包括：模式 ID、已有组件、必需 props、可调参数、默认值、禁用情形、代表镜头、回归样例。

新增组件必须同时满足：
1. 现有组件无法清楚表达指定知识关系；
2. 该模式会在未来重复使用，或此镜头确实有独特表达价值；
3. 有静态首帧、运动关键帧和正常速度预览；
4. 有至少一个边界测试（长文字/最大元素数/短时长/不同背景之一）；
5. 在组件目录中登记，避免相似组件重复建设。

不因某个模型“写起来更方便”就新增组件。先调整数据和 props，最后才扩展代码。

## 7. 镜头级与全片级验收

镜头级：
- 2 秒静帧能看懂主体、关系与文字；
- 正常速度能看出知识关系，而不只是看出元素在动；
- 没有出界、遮挡、标签错位、运动突然跳变；
- 动画结束时信息稳定可读。

全片级：
- 镜头动作不连续三次重复同一方向；
- `snap` 只在重音使用，不能成为默认入场；
- 相邻镜头至少在主体、构图、镜头动作、信息层级中有一项有意承接、一项有意变化；
- 全片主题与色板统一，避免为了“多样”而每镜换画风；
- 至少检查开头、最大信息密度镜头、主要转折、结尾四类关键帧。用户要求降低返工时，关键帧检查是制作验收，不应被“只读代码”取代。

## 8. 试点指标

记录以下数据，而不是凭感觉判断改进：
- 动效选择合适率（人工通过/抽查镜头数）；
- 首次视觉验收通过率；
- 每条视频平均 review 轮数；
- 每条视频重写组件次数；
- 每条视频模型调用/token 与渲染时间。

先用 1 条现有题材建立基线，再在 3 条试点中复测。没有数据前不要宣称新模式库已降低成本。
