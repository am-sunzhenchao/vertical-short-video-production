# 逐知识点视觉规划执行指南（Step 4）

## 单一入口与执行顺序

先只读取本文，按 4A → 4B → 4C → 4D 执行，不一次性全文加载所有视觉规范。每个子步骤只解决一个问题，产出检查通过后再继续；无需额外人工确认，最终统一在 Step 6 Review。

规则优先级：事实与知识覆盖 → 表达清楚与阅读安全 → 全局色板/固定字号 → 组件可执行性 → 运镜与形式多样。形式多样不能抵消前面的失败；准确性、色板与字号均不得作为交换条件放弃。

这里规定执行方式，详细色值、字号与模式定义仍以各自规范文件为唯一来源；本文映射表是候选起点，不替代实际查库或证据。

## 4A · 拆出需要看懂的关系

输入：Step 2 的研究底稿与 Step 3 的叙事、旁白。只处理当前镜的知识目标，不考虑配色、动画或美学风格。

每镜写清：

| 字段 | 要回答的问题 |
|---|---|
| sceneId、knowledgeIds、claimIds | 这一镜对应哪些已核验知识与主张？ |
| knowledgeGoal | 观众看完能解释什么？用一句话写，不写“视觉冲击” |
| knowledgeRelation | 是因果、对照、流程、结构、数据、尺度、分类、纠错还是汇总？ |
| 必须呈现的对象与关系 | 哪些名词、数字、连接、顺序或条件必须画出来？ |
| 证据边界 | 哪些是实测，哪些只能标“示意”？ |

一镜含多个独立知识目标时，先拆镜或选择一个主目标，不强塞多个主模式。发现证据不足回 Step 2，不能靠动画补造事实。

放行：能明确列出主体和关系；只剩一句口号、术语或“科技氛围”而无法解释知识目标，不进入 4B。

## 4B · 先选表达，再选动作

按主关系从下表取一个候选，再描述稳定画面与关键变化。不先选镜头风格再硬套知识。

| 主关系 | visualGrammar 候选 | primaryPattern 候选 | shotLang 候选 | 必须画出的内容 |
|---|---|---|---|---|
| 因果/机制 | 因果示意图 | CAUSE_EFFECT | W1 / I1 | 原因、机制、结果和有依据的连接 |
| A/B、前后对照 | 同尺度对照图 | SIDE_BY_SIDE_COMPARE | C1 / W1 | 相同口径、差异项与限定条件 |
| 步骤/时间顺序 | 纵向流程/时间线 | SEQUENTIAL_REVEAL | W1 / I1 | 顺序、关键节点与先后关系 |
| 内部组成 | 分层结构/拆解图 | STRUCTURE_EXPLODE | E1 / I1 | 整体参照、部件与层级 |
| 数值/趋势 | 数据图表 | DATA_BUILD | C1 | 真实数据、坐标、单位与结论 |
| 路径/迁移 | 路径示意图 | FLOW_FIELD | W1 / I1 | 方向、路径与受控流动，不用随机粒子 |
| 尺度/范围 | 同参照尺度图 | SCALE_EXPANSION | W1 / KG-y1 | 尺度参照和变化范围；无数据注明示意 |
| 分类/选择 | 分支树 | BRANCHING_PATH | W1 / I1 | 分支条件和各自后果 |
| 误区/揭晓 | 预期与事实对照 | QUESTION_REVEAL | W1 / K1 | 预期、证据与纠正；K1不能独占复杂机制解释 |
| 汇总/金句 | 回收已有框架 | SYNTHESIS_LOCKUP | K1 / W1 | 已讲知识的归纳，不新增论点 |

复杂形态演化、局部聚焦或真实媒体场景再查对应 MORPH_SEQUENCE、FOCUS_CALLOUT 或其他语法，不为覆盖所有模式而使用它们。

按需读取：
- `motion-system.md`：只读已选模式的目录行与 motionPlan 字段契约；有参数疑问才读参数基线。
- `镜头语言.md`：只读已选语法与需要的运镜条目；有真实材质/构图兼容疑问才查兼容矩阵。
- 默认 camera=hold、intensity=low、secondaryPattern=null。需要改变时说明知识原因，不因每镜“应该动”就加运镜。

shotLang 是主体与表现语法，不是 styleMode。默认 vox-light 允许在同一 paper 色板与质感下使用图表、手绘流程、等轴测或平涂拆解；兼容矩阵是适配提醒，不按语法名字机械禁用知识表达。实际方案仍须满足固定背景、字形与材质约束。

放行：写出“初始主体 → 哪个关系如何变化 → 最终能读出的结论”。三个卡片淡入但没有因果连接，不算 CAUSE_EFFECT；文字弹跳但没有数值与坐标，不算 DATA_BUILD。

## 4C · 绑定实现与继承全局 token

先完成一份全片配置，再逐镜继承，不逐镜重选。

1. 从 `色板.md` 的“默认设置”和 paper 行一次读取名称、六键实际值及语义映射；默认 styleMode=vox-light。已有批准配置先核对有效性后复用，不重新发明配色。
2. 从 `typography.md` 与 `assets/typography.json` 一次读取 `review-v1-fixed` 完整样式（字号、字重、行高、字体角色）。逐镜填写 textRole / fontRole / colorRole，不重选数值：已有顶部章节标题用sceneHeading（52/800/sans），知识胶囊knowledgeChip（44/900）、机制节点nodeLabel（44/800/sans）、结论conclusion（44/800）；字幕显式handwritten（70/600）。手写镜不改变顶部标题字体。钩子heroTitle96、重音heroSymbol140独立规划，不任意倍乘普通token。
3. 先查 `assets/project-template/src/ui/` 和可执行组件索引，再查目标项目真实组件；确认文件、props和能力，不将旧Effect名称表当成真实库。每镜仍有独立包装；先调整数据和参数，确实无法兑现知识关系才写专用几何，并记录待人工验证状态。
4. 确定素材路线 shot_type：代码动态表达优先 effect；静态数据/结构用 infographic，单一图表用 chart，静态流程用 process；概念矢量用 flat，真实媒体/氛围用 atmosphere，逐笔线稿用 doodle。表达方法与素材路线不是同一个字段。
5. 写 visualElements 与 component.params，包括全部实际显示文字（含顶部标题、出处、符号）、对象、数据、连接、textRole、fontRole、colorRole与呈现顺序。position使用SceneCanvas局部坐标 `{x,y,width,height}`，预算包含SVG偏移、半径、描边和padding；不要仅写“中部”却不给可用空间。组件必须实际读取声明的参数，不能靠硬编码另维护一套文案。精确数据不交给通用生图模型；素材正式生成仍在 Step 7。

默认安全摘要：内容 top≥150、左右≥40，主视觉止于字幕之前；字幕70px、单行≤13视觉字符、bottom≥250，不缩字；背景平涂、遮罩同 bg，不增星空/发光/栏目带/品牌带/视频进度条。

`visual-system.md` 仅在安全区、材质、真实素材、主题覆盖等具体问题出现时读取对应章节；Step 7 实现时再完整检查所用规范。字号与色板不能因按需加载而遗漏实际值。

放行：每处文字有合法 textRole、每处颜色有合法 colorRole，组件能力或待新建理由明确。只有“按规范实现”的泛泛描述不通过。

## 4D · 小批次核对，再拼接全片

长片默认按叙事段落分批，每批约 3–5 镜；短片按实际镜数，不凑数量。每批依次完成 4A–4C，把结果写入同一 `制作过程/视频方案审阅稿.md` 的视觉规划区域，标注“Step 4 待整合，未批准”；不另建四套产物或新事实来源。Step 5 再整合为正式同版 JSON 与草稿。

| 检查 | 必须给出的证据 | 失败回退 |
|---|---|---|
| 知识兑现 | claimId → 具体画面元素/连接/数据，说明观众能看出什么 | 4A / 4B；证据问题回 Step 2 |
| 模式成立 | 关键变化体现知识关系，而非只有装饰动作 | 4B |
| 阅读与 token | 文字角色、颜色角色、阅读空间和字幕隔离 | 4C；装不下改布局或拆镜，不缩字 |
| 制作可执行 | 真实组件路径/参数，或有理由的新建计划 | 4C |
| 相邻镜承接 | 上镜哪个元素/结果进入下镜，构图或信息层级怎样变化 | 4B，必要时回 Step 3 |

每批记录最后一镜的主体、结论与视觉锚点，下批第一镜必须核对这个交接；全部完成后再扫一遍跨批边界、主题一致与知识覆盖。存在未解决项不进入 Step 5 的正常放行评测。

不机械要求信息镜每三镜换族，不为凑主辅语法数量插无意义氛围镜。若连续镜分别增加新证据、机制或层级，且画面有意承接/变化，可以继续同族；无增量或阅读疲劳时才调整。

## 交接到 Step 5

逐镜交接 sceneId、knowledgeIds/claimIds/sourceIds、knowledgeGoal、knowledgeRelation、visualGrammar、shotLang、shot_type、visualElements、完整 motionPlan、component 与查库结果、continuity，并附全片 palette 与 typography 配置和上述检查证据。

这些内容映射到 `video-plan.md` 已有字段：knowledgeGoal/knowledgeRelation 放 motionPlan，检查证据放对应 componentLookup、continuity 与 evaluation 的说明，不增加第二套互不对应的字段名。Step 5 补齐 schema 与评测，Step 6 批准前仍不写生产代码、生成素材或配音。

拆分与批次只是减少单次决策负担，不保证弱模型没有 badcase。是否改善需要用真实知识题材比较知识兑现、规则遗漏和 Review 返工情况，不能仅凭文件缩短宣称效果已提升。
