# 研究驱动的知识短视频工作流

## 目标与输入

输入通常是已写好的文章或资料摘要，少量情况下是零散知识点/笔记。输入只作为研究起点，不自动视为完全正确、完整或可直接照读的脚本。目标是形成一条事实可靠、叙事清楚、视觉表达匹配的中文知识短视频。

## 阶段 A：理解输入与界定问题

1. 阅读全部输入并保存原文到 `source.md`，不覆盖、不静默改写原始材料。
2. 提炼：主题、观众需要回答的核心问题、原文主张、关键术语、时间/地域/对象范围、作者立场。
3. 区分四类信息：
   - `source_fact`：输入材料明确给出的事实或主张；
   - `verified_fact`：已通过可靠来源核验；
   - `interpretation`：对材料的解释或综合；
   - `unknown`：尚无足够证据或存在争议。
4. 找出逻辑跳跃、定义缺失、反例、可能误解点与需要补充的背景。

## 阶段 B：研究与主张核验

1. 把涉及数字、因果、机制、比较、时间、空间、绝对化措辞及争议判断拆成最小可核验主张。
2. 根据风险排序研究优先级；核技术、医学、法律、金融、公共安全、争议历史及精确数字默认至少中风险。
3. 优先使用一手研究、政府/大学/专业机构、标准文件、高质量综述；重要主张尽量交叉核对独立来源。
4. 为每条关键主张记录：主张、风险、来源标题与 URL、发布机构/作者、日期、来源直接支持的范围、局限、核验状态。
5. 不得把搜索摘要当作高风险主张的充分证据；不得编造来源、DOI、引文或研究结论。
6. 若证据冲突，明确展示冲突与各自适用范围；若证据不足，缩小措辞、标注不确定性或删除，不可把猜测写成事实。
7. 依据 `scientific-review.md` 复核改写后的主张。未解决的高风险主张不得作为确定事实进入成片。

## 阶段 C：补充解释与叙事结构

1. 先写一句核心回答，再安排叙事：问题/反直觉钩子 → 必要背景 → 机制或证据逐层展开 → 限定条件/常见误解 → 总结。顺序按主题调整，不机械套模板。
2. 只补充能帮助观众理解核心问题的背景、定义、机制、对比、例子或反例；每项补充必须有来源或明确标注为解释/类比。
3. 区分事实、推断、类比和叙事修辞。类比必须能帮助理解，不能让观众把类比当作真实物理/历史机制。
4. 保留原材料的重要论点；如果需要删除或弱化，应在优化摘要中说明理由。
5. 控制扩写：不是资料越多越好。新增内容应提升准确性或理解度，不服务核心问题的内容应删去。

## 阶段 D：逐镜视觉规划

在编写 Remotion 代码前，为每个场景写结构化规划，至少包括：

```json
{
  "sceneId": "S01",
  "knowledgeGoal": "观众看完该镜应理解什么",
  "claims": ["claim-id-01"],
  "narrationIntent": "提出问题/解释机制/比较证据/总结",
  "visualGrammar": "scientific-diagram",
  "visualDescription": "画面中必须出现的实体、关系、标注与变化",
  "motionMode": "CAUSE_EFFECT",
  "componentReuse": ["existing-component-name"],
  "newComponentNeeded": false,
  "durationEstimateSec": 6,
  "continuityNote": "与上一镜如何衔接",
  "evidenceCaveat": "如需标示示意图/估算/不确定性则填写"
}
```

`visualGrammar` 是表达方法，不是视觉主题；`motionMode` 是运动模式，不是组件名。每镜优先复用已有组件。只有现有组件无法准确表达知识关系时，才提出新组件，并说明必要性、参数、禁用场景和回归验收项。

常用表达方法包括但不限于：科学示意图/剖面、图表、时间线、地图、左右对照、因果链、结构拆解、流程/路径、层级图、动态文字、档案素材、手绘笔记。不是每条视频都需要全部类型。

## 阶段 E：统一主题与运动连续性

1. 默认不向用户询问风格。全片使用一个统一 `visualTheme` / `styleMode`，默认兼容主题为 `tech-mint`；只有用户明确指定或提供参考片时才覆盖。
2. 主题只负责色板、字体、背景、线条与图形质感，不决定每一镜的知识表达方法。
3. 按 `motion-system.md` 从表达意图映射到 12 种标准动效，再映射到现有 Remotion 组件。
4. 避免连续镜头重复同一种动作；动作必须承担揭示、比较、解释、聚焦或总结功能。
5. 画面中出现的数字、箭头、尺度、空间关系和运动暗示必须与已核验主张一致；非数据驱动的模拟明确标注为示意。

## 阶段 F：交付给 Review 的材料

`draft-review.md` 至少包含：

- 原始输入摘要与核心问题；
- 研究摘要与来源清单；
- 关键主张核验表及未解决项；
- 叙事大纲与最终旁白/场景表；
- 每镜 `visualGrammar`、`motionMode`、复用组件与连续性说明；
- 时长估算、质量评测、优化摘要；
- 需要用户决定的事项（只有实质性选择才提问）。

默认不输出强制风格选择表。若用户没有指定风格，系统直接按内容规划；若用户指定主题或参考片，记录为 `visualThemeOverride`。

## 放行条件

- 核心问题与结论清楚；新增解释有依据且不过度扩写；
- 高风险主张没有未解决的确定性陈述；
- 每镜均有知识目标、表达方法和动效计划；
- 视觉表达没有暗示超出证据的结论；
- 已先检查现有组件库；
- 用户 review 通过前不进入正式代码实现。
